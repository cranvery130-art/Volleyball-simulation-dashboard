03공격 상황

※ 상대 팀의 왼쪽/오른쪽은 상대가 네트를 마주 봤을 때를 기준으로 해요. 화면에서는 좌우가 반대로 보일 수 있어요.
왼쪽/오른쪽은 그 시나리오의 팀이 네트를 바라볼 때를 기준으로 해요. 상대 팀 시나리오에 저장하면 화면상으로는 좌우가 반대로 배치돼요.
공을 받는 팀의 정해진 코트 구역(전위/후위 9구역 중 하나)으로 착지해요 — 오른쪽=레프트 구역, 오른쪽 중간=앞차 구역, 오른쪽 끝=레프트백 구역 (왼쪽은 반대: 라이트·빽차·라이트백). 이 구역은 고정이라 "포지션 배정"을 바꾸거나 선수를 드래그해도 달라지지 않아요.
선택한 공격 상황의 위치·속도·페이크·착지 방향이 지금 설정한 값으로 덮어써져요. 이름은 그대로 유지되고, 다음에 그 항목을 선택하면 새로 설정한 내용으로 재생돼요.

    경기 영상 분석 (실험적 기능)

    영상을 올리고 두 팀의 유니폼 색을 클릭으로 지정하면, 그 색과 비슷한 부분을 찾아 왼쪽과 같은 방식의 점으로 표시해요. 완벽한 인식은 아니라서 점 위치는 직접 드래그로 고칠 수 있어요. 카메라가 코트 전체를 위에서 넓게 비출수록 더 정확해요.
    분석 영역을 지정하면 그 안에서만 색을 찾아서 관중석·배경 등의 오탐지를 줄일 수 있어요. 보통 코트 전체가 들어오게 사각형을 그려주세요.
    색상 지정 버튼을 누른 뒤, 영상(잠시 멈춘 상태 권장)에서 해당 팀 선수의 유니폼 부분을 클릭하세요.

    기록은 영상을 바꿔도 사라지지 않아요. 시간을 누르면 그 영상 지점으로 이동하면서, 저장해둔 도트 위치가 있으면 바로 함께 표시돼요.

    🚧 실제 배포 전환 가이드 (참고용, 나중에 진행)

    지금은 코드 저장이 이 미리보기 화면에서만 시도되는 임시 상태예요. 실제로 여러 기기·팀원끼리 코드를 공유하려면 아래 순서대로 Firebase + GitHub + Vercel 구조로 배포하면 돼요. 코드에서 바꿔야 할 부분은 Backend 객체 하나뿐이라, 나머지 로직(로그인 화면, 개설자/수정권한/조회 구분, 상태 저장 등)은 그대로 재사용할 수 있게 만들어 뒀어요.

    1. GitHub 저장소 만들기 — 이 HTML 파일을 새 저장소에 올려요 (예: index.html 하나만 있어도 됩니다).
    2. Firebase 프로젝트 생성 — Firebase 콘솔에서 새 프로젝트를 만들고 "Firestore Database"를 활성화해요 (테스트 모드로 시작해도 괜찮아요).
    3. 웹 앱 등록 & SDK 설정값 받기 — Firebase 프로젝트 설정에서 "웹 앱 추가"를 누르면 apiKey, projectId 등이 담긴 설정 객체를 줘요. 이 값을 이 HTML의 <head>에 Firebase SDK 스크립트와 함께 추가해요.
    4. Backend 객체 교체 — 이 파일의 const Backend = { ... } 부분(설정 코드 안, "storage backend" 주석 옆)을 Firestore 호출로 바꿔요. 예: get은 getDoc(doc(db,'rooms',key)), set은 setDoc(...), delete는 deleteDoc(...). 나머지 코드는 전혀 손댈 필요가 없어요.
    5. Firestore 보안 규칙 설정 — 아무나 모든 코드를 읽고 쓸 수 없도록 규칙을 다듬어요 (최소한 코드 문서 단위로 읽기/쓰기 제한 권장).
    6. Vercel로 배포 — vercel.com에 가입 후 방금 만든 GitHub 저장소를 Import 하면 자동으로 빌드·배포되고 실제 URL이 생겨요.
    7. 확인 — 배포된 URL로 접속해 "새 코드 만들기"가 정상 동작하는지, 다른 기기·다른 사람이 같은 코드+비밀번호로 들어와지는지 테스트해요.

    이 단계를 진행할 준비가 되면, 이 대화(또는 새 대화)에서 "이제 Firebase로 연결해줘"라고 요청하시면 Backend 부분을 실제 Firebase 코드로 교체해 드릴게요. 그 전까지는 이 화면에서 계속 버그 수정과 기능 개선을 진행할게요.
